# fbspider-server 后端代码实现文档

## 一、项目概述

fbspider-server 是一个基于 Flask 的后端服务，为 fbspider 浏览器插件提供数据存储、指令下发、设备管理和开放 API 等能力。同时包含 WebSocket 中继服务，用于与浏览器插件建立实时双向通信。

### 技术栈

| 组件 | 技术栈 | 版本 | 说明 |
|------|--------|------|------|
| HTTP 框架 | Flask | 3.x | RESTful API 服务 |
| WebSocket | websockets | 13.x+ | 与浏览器插件的长连接通信 |
| 数据库 | MongoDB (pymongo) | 4.x+ | 所有业务数据持久化 |
| 前端 | React + Vite | - | 管理面板 SPA |
| 进程管理 | gunicorn + gevent/gthread | - | 生产环境部署 |
| 对象存储 | MinIO (S3 兼容) | 7.x+ | 广告素材存储 |

### 服务端口

| 端口 | 协议 | 用途 |
|------|------|------|
| 7150 | HTTP | Flask API + React 前端静态资源 |
| 7671 | WebSocket | 与浏览器插件的实时通信 |

## 三、核心模块详解

### 3.1 app.py — 主应用入口

**职责**：Flask 应用创建、中间件配置、蓝图注册、前端 SPA 托管、WebSocket 服务启动。

**关键流程**：

1. 创建 Flask 实例，配置 JSON 序列化（兼容 MongoDB 的 datetime/ObjectId 类型）
2. 配置 CORS（允许所有来源访问 `/api/*`）
3. 调用 `init_db()` 初始化 MongoDB 索引
4. 调用 `start_scheduler()` 启动定时任务
5. 注册 10 个蓝图（Blueprint），分别对应不同的 API 模块
6. 调用 `start_ws_server()` 在独立守护线程中启动 WebSocket 服务
7. 配置 React SPA 的静态文件服务（`/` 和 `/assets/*`）
8. 配置旧版 `/static/*` 兼容路由
9. `after_request` 钩子中处理服务端 gzip 压缩（解决 VPN 代理导致的 `ERR_CONTENT_LENGTH_MISMATCH`）

**启动方式**：

```bash
# 开发模式
python app.py

# 生产模式（Docker / gunicorn）
gunicorn --bind 0.0.0.0:7150 --worker-class gthread --threads 8 --workers 1 app:app
```

### 3.3 auth.py — 认证体系

支持三种认证方式，按优先级依次尝试：

1. **API Key**（`X-API-Key` 请求头）
   - 查询 `fbhelper_api_key` 集合，匹配 `key_hash`
   - 校验 `status=active`、`expires_at`、关联用户的 `status=active`
   - 携带 `_api_key_scopes` 字段用于权限校验

2. **Bearer Token**（`Authorization: Bearer xxx` 或 `X-Auth-Token`）
   - 查询 `auth_sessions` 集合，匹配 `token_hash`
   - 校验 `expires_at` 未过期

3. **Session Cookie**
   - 从 `session["auth_username"]` 读取用户名
   - 查询用户表验证

**提供的装饰器**：

| 装饰器 | 说明 |
|--------|------|
| `page_login_required` | 页面级登录校验，未登录重定向 |
| `page_admin_required` | 页面级管理员校验 |
| `api_login_required` | API 登录校验，返回 401 |
| `api_admin_required` | API 管理员校验，返回 403 |
| `api_key_required(scope)` | API Key 或管理员访问，可指定 scope |
| `api_user_manager_required` | admin 或 leader 角色 |

### 3.4 models.py — 数据模型层

直接操作 MongoDB，封装所有数据库 CRUD 操作。

**主要集合（Collection）**：

| 集合名 | 用途 | 关键索引 |
|--------|------|----------|
| `fbhelper_users` | 用户管理 | `username`（唯一） |
| `auth_sessions` | 登录会话 | `token_hash`（唯一） |
| `fbhelper_api_key` | API Key | `key_hash`（唯一，partialFilter） |
| `ad_accounts` | 广告账户 | `account_id`（唯一） |
| `fbhelper_acc` | 插件上报的账户摘要 | `account_id`（唯一） |
| `bm_list` | Business Manager | `user_id + bm_id`（唯一） |
| `bm_ad_accounts` | BM 下的广告账户 | `user_id + bm_id + account_id`（唯一） |
| `ad_account_users` | 广告账户用户 | `user_id + account_id + ad_user_id`（唯一） |
| `pixels` | 像素 | `user_id + pixel_id`（唯一） |
| `pixel_associations` | 像素关联 | `user_id + pixel_id + assoc_type + assoc_id`（唯一） |
| `pixel_purchase_events` | 像素购买事件 | `user_id + pixel_id` |
| `ad_library_items` | 广告库条目 | `user_id + ad_archive_id`（唯一） |
| `campaigns` | 广告系列 | `account_id + campaign_id`（唯一） |
| `command_queue` | 指令队列 | `user_id + status` |
| `action_logs` | 操作日志 | `user_id` |
| `extension_state` | 插件状态 | `user_id + key`（唯一） |

**核心函数**：

- `init_db()`：启动时创建所有索引 + 确保 admin 默认账户存在
- `ensure_default_admin()`：首次运行时创建 admin/admin123456 超级管理员
- `upsert_ad_account()`：广告账户数据写入（同时更新 ad_accounts 和 fbhelper_acc）
- `create_api_key()`：生成 `fbk_` 前缀的 API Key，存储 key_hash
- `get_user_by_api_key()`：API Key → 用户信息（含 scopes）

### 3.5 ws_relay.py — WebSocket 中继服务器

**职责**：管理浏览器插件的 WebSocket 连接，维护设备列表，下发指令，接收结果。

**架构**：
- 独立线程运行，不影响 Flask HTTP 服务
- 使用 `asyncio` 事件循环
- 通过模块级变量（`devices`、`task_results`）与 Flask 共享状态

**共享状态**：

```python
devices = {}        # device_id -> { ws, tabs, connected_at, username }
task_results = {}   # task_id -> { result, created_at }
```

**WebSocket 消息协议**：

| 方向 | type/action | 说明 |
|------|-------------|------|
| 插件→服务端 | `register` | 设备注册，携带 device_id 和 username |
| 插件→服务端 | `heartbeat` | 心跳（30秒一次），更新 last_heartbeat |
| 插件→服务端 | `tab_report` | 上报当前标签页列表 |
| 插件→服务端 | `task_result` | 上报任务执行结果 |
| 服务端→插件 | `authorize_pixel` | 下发像素授权指令 |
| 服务端→插件 | `navigate` / `click` / `toggle_ad` 等 | 通用控制指令 |
| 服务端→插件 | `ping` | 注册确认 |

**设备路由逻辑**（`_resolve_device`）：

优先级从高到低：
1. `device`：直接按设备 ID 前缀匹配
2. `account_id`：广告账户 → ad_accounts.user_id → devices.username → device_id
3. `username`：用户名 → devices.username → device_id
4. 回退：第一个在线设备

**线程安全**：
- `send_command()` 使用 `asyncio.run_coroutine_threadsafe()` 从 Flask 线程安全地向 WebSocket 线程提交异步任务
- 设备断开时自动清理（`finally` 块中 `del devices[device_id]`）

**启动与容错**：
- `start_ws_server()` 在守护线程中启动
- `_ws_thread_target()` 包含 while 循环 + 异常捕获 + 3 秒后自动重试

#### 3.6.6 api_receive.py — 数据上报

接收浏览器插件上报的各类数据：广告账户、BM、像素、广告系列等。

#### 3.6.7 api_serve.py — 数据查询

向浏览器插件提供数据查询服务。

#### 3.6.8 api_commands.py — 指令队列

基于 MongoDB 的指令队列模式：插件轮询获取待执行指令。

### 3.7 scheduler.py — 定时任务调度

**核心功能**：定期将广告账户 DSL（消费限额）数据批量推送到外部回调地址。

**工作方式**：
- 使用线程 + `threading.Event()` 实现定时循环
- 按 `ACCOUNT_DSL_CALLBACK_INTERVAL_MINUTES` 配置的间隔执行
- 每次从 `ad_accounts` / `fbhelper_acc` 集合加载数据
- 按 `ACCOUNT_DSL_CALLBACK_BATCH_SIZE` 分批 POST 到回调 URL
- 请求头携带 `X-Api-Secret` 鉴权
- 日志保存到 `callback_logs/` 目录

### 3.8 manual_callback.py — 手动回调工具

CLI 工具，用于手动触发 DSL 数据推送。

```bash
python manual_callback.py --limit 10 --dry-run
python manual_callback.py --url https://example.com/callback --batch-size 50
```

## 五、部署指南

### 5.1 Docker 部署（推荐）

```bash
cd fbspider-server
docker compose up -d
```

`docker-compose.yml` 配置说明：
- 暴露端口 7150（HTTP）和 7671（WebSocket）
- 挂载 `callback_logs` 目录
- 通过环境变量覆盖 MongoDB URI 和回调间隔
- `restart: unless-stopped` 自动重启

### 5.2 手动部署

```bash
# 1. 安装依赖
pip install -r requirements.txt gunicorn

# 2. 编译前端（如需管理面板）
cd frontend && npm ci && npm run build && cd ..

# 3. 启动服务
gunicorn --bind 0.0.0.0:7150 --worker-class gthread --threads 8 --workers 1 app:app
```

### 5.3 环境变量配置

| 变量 | 必填 | 说明 |
|------|------|------|
| `MONGO_URI` | 是 | MongoDB 连接串 |
| `ACCOUNT_DSL_CALLBACK_URL` | 否 | DSL 回调地址 |
| `ACCOUNT_DSL_CALLBACK_SECRET` | 否 | 回调鉴权密钥 |
| `MINIO_ENDPOINT` | 否 | MinIO 地址 |

## 六、注意事项

1. **gunicorn workers 必须为 1**：WebSocket 共享状态（`devices`、`task_results`）是进程内变量，多 worker 会导致状态不一致
2. **VPN 代理 gzip 问题**：`after_request` 中已做服务端 gzip 压缩，避免 VPN 二次压缩导致 `ERR_CONTENT_LENGTH_MISMATCH`
3. **API Key 安全**：明文 Key 只在创建时返回一次，数据库仅存储 SHA256 哈希
4. **默认管理员**：首次运行自动创建 admin/admin123456，请及时修改密码
5. **WebSocket 重连**：服务端有 3 秒自动重试机制，插件端有 5 秒自动重连
