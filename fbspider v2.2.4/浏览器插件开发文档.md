# fbspider 浏览器插件开发文档

## 一、插件概述

### 1.1 基本信息

| 项目 | 值 |
|------|-----|
| 插件名称 | fbspider |
| 版本 | 2.2.4 |
| Manifest 版本 | Manifest V3 |
| 开发者 | Veryfb |
| 用途 | Facebook 资产自动化管理工具 |

### 1.2 核心功能

1. **BM 界面切换**：在 Facebook Business Manager 新旧界面之间切换
2. **广告账户数据采集**：自动抓取广告账户信息并上报后端
3. **像素授权自动化**：通过 WebSocket 接收后端指令，自动完成像素授权操作
4. **广告管理辅助**：广告开关、预算修改等自动化操作
5. **广告库素材采集**：从 Facebook 广告库抓取广告素材

## 四、content-pixel.js 详解（像素授权核心）

### 4.1 整体架构

采用 IIFE（立即执行函数表达式）封装，避免全局变量污染。

```
content-pixel.js
├── 常量定义（WS_URL、重连间隔）
├── 状态变量（ws、deviceId、registered）
├── generateDeviceId()       生成唯一设备 ID
├── getUsername()            提取当前登录用户名
├── sendWs(msg)              发送 WebSocket 消息
├── registerDevice()         注册设备到后端
├── sendHeartbeat()          发送心跳
├── sendTaskResult()         上报任务结果
├── handleAuthorizePixel()   处理授权指令（入口）
├── executeAuthorization()   执行授权（路由到 API 或点击方案）
├── authorizeViaAPI()        方案 A：调用 API 授权
├── authorizeViaClick()      方案 B：模拟点击授权
├── connect()                WebSocket 连接管理
└── 初始化代码               生成 deviceId + connect + 心跳定时器
```

### 4.2 WebSocket 连接管理

**连接地址**：`ws://localhost:7671`

**生命周期**：
1. 页面加载时生成唯一 `deviceId`（格式：`px_` + 随机字符 + 时间戳后4位）
2. 建立 WebSocket 连接
3. 连接成功后发送 `register` 消息
4. 每 30 秒发送 `heartbeat`
5. 断开后 5 秒自动重连

**消息格式**（发往服务端）：

```javascript
// 设备注册
{ "type": "register", "device_id": "px_abc123def", "username": "user@example.com" }

// 心跳
{ "type": "heartbeat", "device_id": "px_abc123def", "username": "user@example.com" }

// 任务结果
{ "type": "task_result", "task_id": "a1b2c3d4", "result": { "status": "ok", ... } }
```

**消息格式**（接收服务端）：

```javascript
// 像素授权指令
{ "action": "authorize_pixel", "task_id": "a1b2c3d4", "params": { "pixel_id": "...", "target_account_id": "..." } }

// Ping（注册确认）
{ "action": "ping", "task_id": "..." }
```

### 4.3 授权执行流程

```
收到 authorize_pixel 指令
       │
       ▼
检查当前页面是否为 fbspider.com
       │ 否 → 返回错误
       ▼
检查是否在像素授权页面（#/pixel/index）
       │ 否 → 导航到该页面，等 1.5 秒
       ▼
调用 executeAuthorization()
       │
       ▼
authorizeViaAPI() ← 当前默认方案
       │
       │ 调用 fbspider.com 的像素授权 API
       │ credentials: 'include'（携带 Cookie）
       │
       ▼
返回结果 → sendTaskResult()
```

## 六、开发与调试

### 6.1 安装插件

1. 打开 Chrome，进入 `chrome://extensions/`
2. 开启「开发者模式」
3. 点击「加载已解压的扩展程序」
4. 选择 `fbspider v2.2.4` 目录

### 6.2 调试 content-pixel.js

1. 打开 fbspider.com 页面
2. F12 → Console，搜索 `[Pixel]` 前缀的日志
3. 关键日志：
   - `[Pixel] Content script 已加载, device_id=px_xxx` — 脚本加载成功
   - `[Pixel] WebSocket 已连接` — WS 连接成功
   - `[Pixel] 注册设备: px_xxx` — 注册成功
   - `[Pixel] 开始授权: pixel_id=xxx` — 收到授权指令
   - `[Pixel] 通过接口授权` — 正在执行 API 授权
   - `[Pixel] 发送任务结果: xxx` — 结果已上报

### 6.4 常见问题排查

| 问题 | 排查步骤 |
|------|----------|
| 插件未加载 | 检查 manifest.json 是否有语法错误；确认 content-pixel.js 已加入 content_scripts |
| WebSocket 连不上 | 确认后端 7671 端口已启动；检查 `ws://localhost:7671` 是否可达 |
| 用户名为 null | 检查 fbspider.com 页面 DOM 结构，调整 getUsername() 逻辑 |
| 授权失败 | 检查 Network 面板中 API 请求的实际参数和响应 |
| 收不到指令 | 确认设备注册成功（看日志）；确认后端设备列表中有该设备 |

## 七、注意事项

1. **Manifest V3 限制**：Service Worker 没有 DOM 访问，所有页面操作必须在 content script 中完成
2. **代码已混淆**：`background.js`、`popup.js`、`common.js`、`content-main.js` 均已混淆，不可直接修改
3. **content-pixel.js 未混淆**：这是唯一可读可改的核心文件
4. **CORS**：fbspider.com 的 API 可能需要 Cookie 认证，`authorizeViaAPI` 中使用了 `credentials: 'include'`
5. **重连机制**：WebSocket 断开后 5 秒自动重连，不需要手动处理
6. **心跳间隔**：30 秒一次，后端通过心跳更新 `last_heartbeat` 字段
